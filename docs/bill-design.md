# 记账功能设计文档## 1. 功能概述拍照/截图上传小票或账单，AI 多模态模型自动识别金额、商户、分类，结构化存入数据库。支持手动录入、按日期/分类筛选、月度统计报表。---## 2. AI 模型选型当前项目使用火山引擎 Ark API，现有模型为纯文本模型 `doubao-seed-character-251128`。记账需要**图像识别**能力，需替换为豆包多模态模型：| 项目 | 值 ||------|-----|| 模型名称 | `doubao-vision-pro-32k` || 能力 | 文本对话 + 图片理解（OCR、语义识别） || API Key | 复用现有 `ARKAPIKEY` || 调用方式 | 与现有 chat 模型相同的 Ark SDK，传入多模态 Message（图片 URL 或 Base64） |### .env 新增配置```envARKAPIKEY=6683ac59-3e35-48cb-8084-94666b9c73bcMODEL=doubao-seed-character-251128EMBEDDER=doubao-embedding-vision-251215VISION_MODEL=doubao-vision-pro-32k```> 记账模块读 `VISION_MODEL`，聊天模块继续读 `MODEL`，互不影响。### AI 提示词设计用户上传图片后，后端构造如下多模态请求：```System: 你是一个专业的账单识别助手。用户会上传小票、账单、支付截图等图片。请从图片中提取以下信息，严格以 JSON 格式返回，不要添加任何其他文字：{  "amount": 金额(数字),  "merchant": "商户名称",  "category": "分类(只能从以下选择: 餐饮美食, 交通出行, 购物消费, 生活缴费, 休闲娱乐, 医疗健康, 教育学习, 住房物业, 人情往来, 职场办公, 其他)",  "date": "日期(YYYY-MM-DD，如果图片中没有明确日期则返回今天的日期)",  "description": "简要描述这笔消费"}如果图片模糊或无法识别，返回：{"error": "无法识别该图片，请重新上传或手动录入"}```---## 3. 数据库表设计### 3.1 记账分类表 `bill_categories````sqlCREATE TABLE `bill_categories` (  `id`         BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,  `user_id`    BIGINT       NOT NULL          COMMENT '所属用户，0 表示系统默认分类',  `name`       VARCHAR(30)  NOT NULL          COMMENT '分类名称',  `icon`       VARCHAR(30)  NOT NULL DEFAULT '' COMMENT '图标 emoji',  `type`       TINYINT      NOT NULL DEFAULT 0 COMMENT '0=支出 1=收入',  `sort_order` INT          NOT NULL DEFAULT 0 COMMENT '排序权重，越小越靠前',  `created_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,  `updated_at` DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,  INDEX `idx_bill_categories_user` (`user_id`)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='记账分类';```**系统预置分类（user_id=0）：**| name | icon | type | sort_order ||------|------|------|------------|| 餐饮美食 | 🍜 | 0 | 1 || 交通出行 | 🚗 | 0 | 2 || 购物消费 | 🛒 | 0 | 3 || 1 | 3 || 其他 | 📌 | 0 | 99 |### 3.2 账单记录表 `bills````sqlCREATE TABLE `bills` (  `id`          BIGINT       NOT NULL AUTO_INCREMENT PRIMARY KEY,  `user_id`     BIGINT       NOT NULL          COMMENT '所属用户',  `category_id` BIGINT       NOT NULL          COMMENT '分类 ID',  `amount`      DECIMAL(12,2) NOT NULL         COMMENT '金额',  `type`        TINYINT      NOT NULL DEFAULT 0 COMMENT '0=支出 1=收入',  `merchant`    VARCHAR(100) NOT NULL DEFAULT '' COMMENT '商户名称',  `description` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '消费描述',  `bill_date`   DATE         NOT NULL          COMMENT '账单日期',  `image_url`   VARCHAR(500) NOT NULL DEFAULT '' COMMENT '小票图片存储路径',  `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,  `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,  `deleted_at`  DATETIME     DEFAULT NULL      COMMENT '软删除',  INDEX `idx_bills_user_date` (`user_id`, `bill_date`),  INDEX `idx_bills_user_category` (`user_id`, `category_id`),  INDEX `idx_bills_deleted` (`deleted_at`)) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账单记录';```### 3.3 图片存储策略- 前端上传图片 → 后端接收 multipart form- 后端将图片保存到 `C:\goProj\backend\uploads\bills\{user_id}\{timestamp}.jpg`- `image_url` 字段存储相对路径 `uploads/bills/{user_id}/{timestamp}.jpg`- Gin 静态文件路由映射 `uploads` 目录---## 4. 后端接口设计### 4.1 新增路由在 `main.go` 的 `protected` 路由组下新增：```go// 记账模块protected.POST("/bill/upload", handlers.UploadBillImage(db))           // 上传小票图片protected.POST("/bill/recognize", handlers.RecognizeBill(db))         // AI 识别图片protected.POST("/bill/create", handlers.CreateBill(db))               // 手动创建/确认 AI 识别结果protected.GET("/bill/list", handlers.ListBills(db))                   // 查询账单列表（分页+筛选）protected.GET("/bill/detail/:id", handlers.GetBillDetail(db))         // 账单详情protected.PUT("/bill/update/:id", handlers.UpdateBill(db))            // 修改账单protected.DELETE("/bill/delete/:id", handlers.DeleteBill(db))         // 删除账单protected.GET("/bill/stats/monthly", handlers.MonthlyStats(db))       // 月度统计protected.GET("/bill/categories", handlers.ListCategories(db))        // 获取分类列表protected.POST("/bill/category/create", handlers.CreateCategory(db))  // 自定义分类protected.DELETE("/bill/category/delete/:id", handlers.DeleteCategory(db)) // 删除自定义分类// 静态文件服务r.Static("/uploads", "./uploads")```### 4.2 接口详细说明#### ① `POST /api/bill/upload` — 上传小票图片- 请求：`multipart/form-data`，字段名 `image`，支持 jpg/png- 大小限制：5MB- 响应：`{ code: 0, data: { image_url: "uploads/bills/1/1712486400.jpg" }, message: "ok" }`#### ② `POST /api/bill/recognize` — AI 识别图片- 请求：`{ image_url: string }`- 后端读取图片文件 → 转 Base64 → 调用 VISION_MODEL → 解析返回的 JSON- 响应：`{ code: 0, data: { amount: 35.5, merchant: "美团外卖", category: "餐饮美食", date: "2025-04-07", description: "午餐外卖" }, message: "ok" }`#### ③ `POST /api/bill/create` — 创建账单- 请求：```json{  "category_id": 1,  "amount": 35.5,  "type": 0,  "merchant": "美团外卖",  "description": "午餐外卖",  "bill_date": "2025-04-07",  "image_url": ""}```- 响应：`{ code: 0, data: { id: 1 }, message: "ok" }`#### ④ `GET /api/bill/list` — 账单列表- 查询参数：`page=1&size=20&year=2025&month=4&category_id=0&type=0`- `category_id=0` 表示不筛选分类，`type=0` 表示不筛选收支类型- 响应：```json{  "code": 0,  "data": {    "list": [      {        "id": 1,        "category_id": 1,        "category_name": "餐饮美食",        "category_icon": "🍜",        "amount": 35.5,        "type": 0,        "merchant": "美团外卖",        "description": "午餐外卖",        "bill_date": "2025-04-07",        "image_url": "",        "created_at": "2025-04-07T12:00:00Z"      }    ],    "total": 128,    "summary": {      "expense": 3856.5,      "income": 15000    }  },  "message": "ok"}```#### ⑤ `GET /api/bill/detail/:id` — 账单详情- 路径参数：`id`- 响应：单条账单完整信息#### ⑥ `PUT /api/bill/update/:id` — 修改账单- 请求体同 create- 权限校验：只能修改自己的账单#### ⑦ `DELETE /api/bill/delete/:id` — 删除账单- 软删除- 权限校验：只能删除自己的账单#### ⑧ `GET /api/bill/stats/monthly` — 月度统计- 查询参数：`year=2025&month=4`- 响应：```json{  "code": 0,  "data": {    "total_expense": 3856.5,    "total_income": 15000,    "balance": 11143.5,    "daily_stats": [      { "date": "2025-04-01", "expense": 120, "income": 0 },      { "date": "2025-04-02", "expense": 45.5, "income": 0 }    ],    "category_stats": [      { "category_id": 1, "category_name": "餐饮美食", "category_icon": "🍜", "amount": 1200, "count": 35 },      { "category_id": 2, "category_name": "交通出行", "category_icon": "🚗", "amount": 560, "count": 12 }    ]  },  "message": "ok"}```#### ⑨ `GET /api/bill/categories` — 获取分类列表- 查询参数：`type=0`（0=支出 1=收入，不传返回全部）- 返回系统预置分类 + 用户自定义分类#### ⑩ `POST /api/bill/category/create` — 创建自定义分类- 请求：`{ name: "咖啡", icon: "☕", type: 0 }`#### ⑪ `DELETE /api/bill/category/delete/:id` — 删除自定义分类- 只能删除用户自己创建的分类，系统预置分类不可删---## 5. 后端文件变更清单### echarts`），国内加载快、文档全、功能够用。### 图片上传大小限制Gin 默认 body 大小有限制，需在 `main.go` 中设置：```gor.MaxMultipartMemory = 8 << 20 // 8MB```### AI 识别兜底图片识别失败时，前端提示"识别失败，请手动填写"，表单字段清空等待手动输入。不阻塞正常使用流程。### 所有新增文件的换行符全部使用 CRLF（`\r\n`）。
